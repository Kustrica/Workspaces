# Project Context

## Project Overview
"Workspaces" is a WebExtension for browser tab and workspace management (designed for Firefox and Chromium browsers). It allows users to group tabs into workspaces, switch between workspaces smoothly, hide/show workspace tabs using browser tab management APIs, and maintain automatic and manual tab backups.

## Stack & Architecture
- **Tech Stack**: Vanilla HTML5, CSS3, JavaScript (ES6+), WebExtension Manifest V3 (MV3).
- **Core Files**:
  - `manifest.json`: Extension manifest V3 defining permissions, background scripts, sidebar action, and commands.
  - `background.js`: Background script handling state management, tab switching, session storage sync, context menus, keyboard shortcuts, and auto-backups via `browser.alarms`.
  - `sidebar.html` / `sidebar.js`: Sidebar panel UI for managing workspaces, viewing active tabs, actions, and logs.
  - `options.html` / `options.js`: Extension settings page for managing shortcuts, backup configuration, data export/import, and theme.
  - `i18n.js` / `_locales/`: Multi-language internationalization system.
- **New-tab assignment order**: opener tab workspace (`openerTabId`, re-fetched) → active tab in the same window → `currentWorkspaceId` / `lastActiveWsId` → first workspace fallback. Session values are used on rebuild/startup, not for user-opened tabs in `onCreated` (that path was pushing tabs into Main).
- **Background wake**: Listeners must not `saveState()` during init. After load, re-read storage (merge sidebar writes), then `repairWorkspaceVisibility({ allowActivate: false })`. Provisional `onCreated` during init is memory-only (no session). `SWITCH_WORKSPACE` / `SHOW_ALL_TABS` wait for init via `runWhenReady`.
- **Empty workspaces list**: An explicit `workspaces: []` must not resurrect default Main/Study workspaces.
- **Auto-backup alarms**: `autoBackupAlarm` is created/refreshed on script load, `onInstalled`, `onStartup`, and when backup settings change. Startup backups still use `onStartup` → `createAutoBackup('startup')` independently of the periodic alarm.

### Firefox account synchronization (1.19.8)

#### Ownership and transport

`sync.js` contains document construction, comparison, merging, compression and storage IO. `background.js` owns the state machine and the live tab APIs. Options and Sidebar send messages to the background controller. Options never directly applies an account snapshot. Sync uses only `browser.storage.sync`, with extension ID `workspaces@kustrica.addon`. There is no custom server or separate authentication token.

There are two separate stages:

1. The extension collects live workspaces and tabs, reconciles them with the current local `storage.sync` copy, and publishes a snapshot into that local copy.
2. Firefox transports storage keys through the Mozilla account to other devices. The receiving extension validates and incrementally applies the snapshot after it arrives.

Writing to `storage.sync` is not proof that another device has received anything. The API does not expose the account email, transport progress, a delivery receipt, or a command to force account synchronization. The device roster is an extension-generated label and last-seen record, not the Firefox account's device list. A green enabled status indicates the local controller is available, not that every peer has matching tabs.

Firefox controls extension-data transport. After a local tab or workspace change, the extension waits five seconds without another change, then prepares and writes a compressed snapshot only if its contents changed. Firefox storage-change events trigger incoming validation/application. The extension does not poll in the background or claim a server-side delivery receipt. The WebExtension API exposes storage changes, not an account-sync-complete event. Reference: [Mozilla storage.sync documentation](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync).

#### Snapshot schema and local state

The version-2 document contains `v` (schema version), `ts` (creation time), `dev` (author device), `ws` (ordered workspaces), `t` (tab rows by workspace), `s` (selected settings), `x` (deletion tombstones), and optional `g: {fp, ts}` (a receipt for the last acknowledged history compaction). Workspace rows contain `i/n/c/o/r/m` for ID, name, icon, order, revision and modification time. A tab row is either its complete URL string or `{u, g?, a?}` for complete URL, optional group metadata, and URL birth time. Equal URL rows remain separate rows. Browser tab IDs, live workspace maps, saved backups, action logs, active-tab IDs, and cookies are not transported. Native browser group IDs are not portable across devices.

URL comparisons use the complete string, including path, query parameters and fragment. No host-only normalization, removal of `?…`, or URL canonicalization is performed. Blank/new-tab, extension and most `about:` pages are excluded. Reader URLs are retained. A synced tab keeps its requested URL as the sync identity through the initial redirect chain. `{url, actualUrl, settled}` is persisted in the native tab session as `syncIdentity`, so background wake and Firefox restoration retain the identity. A subsequent navigation replaces it and records the old URL as closed. Restoring a snapshot cannot reverse a shop's server-side redirect or recover product URLs that an older snapshot already lost.

`storage.local` holds device ID, joined/enabled state, join time, per-source received-update times, preferences, `syncBaseFp`, `syncBaseDoc`, workspace revisions, tombstones, and URL birth times. `syncBaseDoc` is the last successful local publish/apply ancestor. Settings transported are theme, language, sidebar control mode, and backup preferences listed in `SYNCED_SETTING_KEYS`. Action logs themselves are deliberately excluded from the document.

#### Reconciliation and application

New devices never silently overwrite a nonempty account snapshot. A device with local workspaces asks once to replace or merge. A pristine device asks once before adopting the account session. Routine member synchronization is automatic. First-join matching may combine same-name workspaces. With a common ancestor, established workspaces are matched by ID, preserving distinct same-name spaces.

The fingerprint covers workspace metadata/order and every URL row, including duplicate counts. Settings are reconciled separately. Decisions compare local and received fingerprints with the saved ancestor, rather than comparing a freshly collected `Date.now()` timestamp. Local changes publish; both remote-only and concurrent changes reconcile explicit operations. A local publication does not establish that a peer received that ancestor. A stale snapshot cannot authorize a close merely by omitting a tab. An own-device metadata author is never enough to ignore newer local tabs.

With a valid local ancestor, duplicate URL counts use three-way differences, but reductions require explicit close records and cannot remove a birth newer than the observed close. For a URL absent from the ancestor, positive tab birth timestamps group additions already replicated across devices so a stale empty ancestor does not count the same opening twice; distinct birth cohorts remain separate tabs. Old cohorts remain subject to close records. During initial join or migration without an ancestor, merging uses maximum URL counts and per-URL close tombstones. Workspace deletions use workspace tombstones, and closed URLs carry time plus count. Birth metadata is persisted during local edits; a reopen is stamped after its observed close, even when device clocks differ. Joined devices publish a canonical fingerprint of their applied deletion history. Once every enabled, joined device has acknowledged the same history, the history is compacted. Peer roster acknowledgement changes trigger maintenance. The replacement carries a short compaction receipt; missing history without a matching receipt is treated as a stale copy, not as authorized cleanup. Local history is committed only after the replacement write succeeds. Tombstones also expire after 30 days, so very old offline devices outside that retention window cannot be assumed to know every historical deletion.

When local and remote URL fingerprints match, tombstones are reconciled and compacted separately. If acknowledged history is cleared, the compacted tombstone document is republished even though no tab URL changed.

Apply calculates a multiset difference and changes only missing/excess tabs. Immediately before creation, the live guard compares the complete desired multiset to current counts. Passing the already-subtracted delta to this guard would subtract existing tabs twice. Join replace/merge uses this same incremental path. Applying never resets every tab through the JSON import path. Created tabs retain workspace ownership and native session mapping. Closures clear maps explicitly because normal tab listeners are suppressed during apply. Each affected window receives a visible survivor before its last visible tab is closed. Normal workspace visibility is then repaired across windows.

Sync triggers and mutating messages enter one promise queue. Controller initialization shares one promise. Apply temporarily suppresses normal restore-sensitive listeners and sync scheduling. A failed tab creation or closure leaves the target unacknowledged, reports an apply error, and emits no success pulse. Completed partial changes are kept for the next retry rather than marking an incomplete target as synchronized.

#### Compression, quotas and partial delivery

The quota is persistent storage capacity, not a per-transfer allowance: 102400 bytes total, 8192 bytes per item, and 512 items. `unlimitedStorage` does not lift `storage.sync` limits. CompressionStream gzip is used when available, followed by base64 and chunks of up to 6000 characters. The plain fallback sizes chunks against UTF-8 and JSON quoting too. Meta records encoding, chunk count, body length, data fingerprint, timestamp, author, key namespace and SHA-256 of the encoded body.

The previous implementation allocated a new key generation on every write and counted both complete snapshots. A 76 KB snapshot needed approximately 152 KB to update, even though the quota display showed only the existing 76 KB. Version 1.19.8 reuses the current chunk namespace, including legacy slots, so quota accounting includes the resulting values, roster keys, and any trailing chunks still awaiting cleanup. Unreferenced orphan generations are retired, and unused tail chunks are removed after the successful replacement. A rejected write preserves the active snapshot.

Firefox resolves and delivers keys independently. Metadata and chunks are not a cross-device transaction. Readers require matching length, SHA-256 and data fingerprint before applying a snapshot. Mixed or missing chunks produce waiting state and leave live tabs untouched. Only the device named by the winning metadata may repair mixed chunks, and only when its saved snapshot reproduces that exact digest. Peers wait for complete delivery. Chunk arrival itself retriggers reads. Both devices should run the new version, because old writers still allocate extra generations and old readers do not enforce the digest.

Compression greatly increases the number of URLs that fit, but arbitrary data cannot fit into a finite 100 KB quota. Gzip-resistant URLs and large custom icons can still exhaust it. The error states that compressed storage exceeds the Firefox limit and that local tabs are preserved. Options shows raw and compressed sizes, reduction, total quota use and decoded tab/workspace/deletion counts. Detailed storage accounting stays internal. Cleanup removes unreferenced generation chunks whose embedded generation time is older than the active metadata timestamp or at least 24 hours old; recent in-flight generations are retained. Different devices can temporarily show different usage because Firefox has not delivered the same keys yet. Equal byte totals do not prove equal local tab lists or successful application.

#### Feedback and settings

Breathing light is emitted after a successful apply that actually opens or closes tabs. Idle checks, identical snapshots, settings-only changes, workspace-only changes, in-progress applies and failed applies are silent. `syncBreathEnabled` and `syncBreathTheme` are local preferences shared by Options and Sidebar on this device. The checkbox is in the breathing-light row. Disabling light removes an active animation immediately and does not disable synchronization. The count toast remains separate. Color selection deliberately previews the light when enabled.

Sidebar retains cached tab counts when rebuilding rows, ignores equivalent workspace updates, ignores unchanged language writes, and discards outdated asynchronous count results. Repeated identical pulls avoid writing settings and no longer advance the last exchange timestamp. That timestamp still means a local publication/application, not confirmed remote delivery.

#### Guide for a faster two-device exchange

1. Install the same extension version on both devices. Sign in to the same Mozilla account and enable Add-ons in Firefox Sync. Enable sync in Workspaces and finish any first-join choice.
2. After a local tab or workspace change, Workspaces waits five quiet seconds before preparing and writing a changed snapshot. Keeping Options open is not required.
3. Firefox transfers extension data about every ten minutes; selecting Sync Now from Firefox's account menu requests a transfer. The receiving extension applies a validated update automatically. There is no Workspaces manual-check button.
4. If both devices changed data, repeat Firefox Sync Now after the merged snapshot has been published, so the merged result returns to both peers. A single simultaneous click on both devices is not a delivery guarantee.
5. Verify the actual workspace/tab lists and the absence of pending join or apply errors. Compare complete product/search URLs and duplicate counts. Equal quota totals alone are insufficient.

The automated checks cover large replacement, full URLs, duplicate counts, redirects, settings writes, independent edits, partial payloads and failed applies. Firefox 156.0.1 in a fresh headless profile verifies extension installation, native compression, the translated switch, its persistence and light suppression. End-to-end account delivery between the user's computer and laptop remains a separate manual check.

## Constraints & Rules
- Firefox & Chromium compatibility (Manifest V3).
- Strict adherence to non-persistent background script lifecycle (event page / service worker). Global handlers must not trigger side-effects like background task executions on simple script load.
- Avoid unnecessary permissions (e.g. `<all_urls>` host permissions) to preserve privacy and prevent security warnings.
- Permission `"alarms"` is required for scheduled auto-backups; without it `browser.alarms` is unavailable and only startup backups work.
- `switchWorkspace` must not claim unmapped tabs into the previous workspace (causes tabs to migrate into Main during races with `onCreated`).
- Hide order when switching: show target tabs → activate a tab that belongs to the target workspace → then hide others.
- `currentWorkspaceId` must NEVER change as a side effect of closing a tab. If a window runs out of tabs for the current workspace, only open a fresh tab in that SAME workspace — never search for/jump to a different workspace that happens to have a leftover tab (this was the root cause of tabs silently ending up in an unopened workspace; see STEP-15/16 in PLAN.md).
- On cold start, if 100% of restored tabs have no recoverable session/legacy workspace mapping (session data lost — private browsing, forced shutdown, fresh profile) while more than one workspace exists, do not funnel them all into `currentWorkspaceId`; fail safe into All Tabs mode and log a `SAFE_MODE_ALL_TABS` entry instead (see STEP-17).
- `img:`-type workspace icons must have an `onerror` fallback (→ 📁) everywhere they're rendered (workspace list, move-menu, History log) so a missing/broken custom icon file never shows a broken-image glyph.
- Default workspace lists (`getLocalizedDefaults()` in `background.js`, `getDefaultWorkspaces()` in `sidebar.js`) are duplicated by necessity (no shared module across background/sidebar contexts) and must be kept in sync by hand.
- **Firefox `tabs.hide()` caveat:** closing the last *visible* tab in a window while every other tab in it is hidden (a different workspace) can make Firefox treat the window as tab-less and destroy it — or quit the whole browser if it was the last window. There is no cancelable "before tab removed" event. Defense: immediately `tabs.show()` other tabs already in the window (faster than `tabs.create`), then switch into a workspace that owns them. Advise users to enable `Settings → General → Startup → "Open previous windows and tabs"`.
- Auto-backup frequency is stored in **minutes** (`autoBackupFreqIsMinutes: true`). Default is **60 (1 hour)**. Legacy values `1|3|6|8|12|24|72|168` meant hours and are migrated ×60 on load. Invalid/missing values are normalized so the options `<select>` always has a matching option.
- `switchWorkspace(workspaceId, preserveActiveTab, { windowId })` must receive an explicit `windowId` when called from background restore/import — `currentWindow: true` is unreliable there and left all restored tabs visible.
- **i18n rule:** any new user-facing string must be added to **all** `_locales/*/messages.json` files (currently 19 locales), not only `en`/`ru`.
- **Crash Recovery & Orphan Policy:** To guarantee session stability identical to commit `8479da3`, artificial snapshot auto-recovery (`maybeRecoverAfterUnexpectedClose`) is completely removed from startup and tab close events. The extension strictly relies on Firefox native session restoration (`browser.sessions.getTabValue` / `setTabValue`). Furthermore, `switchWorkspace` must NEVER adopt visible unassigned tabs ("orphans") into the destination workspace during switching or leaving All Tabs mode; unmapped tabs are strictly hidden to prevent mass-migration.
- **Sidebar Three-State Toggle (Phase 10):** The sidebar action toggle button (`#toggle-actions-btn`) supports three display states: hiding controls (`hidden`), showing workspace action icons (`actions`), and displaying active tab counts per workspace (`counts`). Icons must conform to `--icon-filter` for light/dark themes, and UI copy must follow anti-slop principles (clean typographic hierarchy without garish badges).
- **Session Restoration & Storage Snapshot Preservation (Phase 11):** When Firefox restarts, restored tabs receive new integer IDs while old IDs remain in `storage.local`. During background initialization, after `rebuildTabWorkspaceMapFromOpenTabs` rebuilds the mapping from native sessions (`browser.sessions`), subsequent storage merges (`applyStorageSnapshot` / `pendingStoragePatches`) MUST pass `{ preserveTabMaps: true }` to prevent stale storage snapshots from overwriting the live tab mappings. Furthermore, startup visibility repair must query all normal windows via `browser.windows.getAll` rather than assuming a single active background window.
- **Last-active tab per workspace (Phase 12):** `workspaceActiveTabMap` must never be rebuilt as "first tab in query order". On rebuild: keep remembered IDs that still point to open tabs in the same workspace → override with currently `tab.active` → gap-fill by highest `tab.lastAccessed`. When leaving a workspace, only record the active tab if `tabWorkspaceMap[active] === leavingWorkspaceId`.
- **Cross-device sync (1.19.8):** Join-once on new devices. Established members reconcile against a local common ancestor. Device roster keys `sync_dev_*` / leave `sync_leave_*`. Settings include theme/language/sidebar/backup preferences. Action logs stay local. Quotas remain 100 KB / 8 KB/item. See the synchronization architecture and guide above.
- **Sync closes (1.19.14):** Keep URL count tombstones and durable reopen birth times. A saved local publication is not a peer delivery receipt. Every member reconciliation, including remote-only changes, requires close facts before reducing URL counts. Joined enabled devices acknowledge their applied history; compaction requires all acknowledgements and a successful replacement write, and publishes a short receipt. Peer roster changes also trigger maintenance. Local tab/workspace changes start a trailing 5-second snapshot debounce. Firefox controls network delivery; storage change events trigger validated pulls.
- **Duplicate URLs (1.19.8):** Sync tab lists use export/import-shaped rows, with full query strings/fragments and duplicates retained. A durable local-only `syncBaseDoc` enables three-way URL-count reconciliation of concurrent edits. Legacy devices without an ancestor use close-count tombstones until the next successful agreement. Established workspaces are matched by ID, even when their names are identical.
- **Incremental join/apply:** Join merge and replace use the same incremental apply as routine sync. Successful closes explicitly remove tab mappings because restore guards suppress normal removal listeners. Every affected window receives a visible safety tab when needed before closing its last visible tab. Failed creates/closes leave the agreed ancestor unchanged and report an apply error.
- **Redirect identity:** A freshly created Firefox tab may report `about:blank` with status `complete`. This is not a settled synced tab. Only completion on a syncable URL settles it. Requested URLs survive initial redirects and are persisted in tab session values across background wake/restart.
- **Quota transport:** Native gzip + base64 in 6000-character chunks, with a SHA-256 payload digest. Replacements reuse the active key namespace and remove orphaned generations before quota preflight while retaining the referenced payload. Per-key partial delivery waits for a matching digest. Only the author of the winning metadata repairs a mixed payload from its durable local snapshot. Limits are 102400 total bytes and 8192 bytes per item, including keys, JSON and device records. Auto-backups and History logs remain local.
- **Sync UI:** Unchanged settings are not rewritten. Sidebar language reloads only on a changed language value. A local `syncBreathEnabled` checkbox controls the edge pulse on both pages. Automatic pulses require successful tab additions/removals, with no pulse for checks or workspace/settings-only edits. Count badges retain their last values while refreshing and the fixed overlay is contained outside page layout.
- **Apply progress UI:** `background.js` broadcasts tab-apply progress only when the diff contains tab changes. Options and Sidebar render the same compact fixed overlay from `sync-progress.js`/`sync-progress.css`; it reports opening/closing/finishing, phase counts, and an overall progress bar without changing document layout. Only successful creates and confirmed closes advance the count. Failed or incomplete applies remain below 100% and show an error state. Messages are localized in all 19 locales.
- **Firefox transfer guide:** Sign into the same Mozilla account on both devices and enable add-on synchronization. Each profile prepares a changed snapshot five quiet seconds after a local tab/workspace edit, and applies validated Firefox storage-change events as they arrive. Firefox controls transfer between devices; its account menu > Sync Now requests a transfer. The UI shows the last local preparation and, per source device, when this profile last observed its new copy in storage. The API does not expose server-side delivery completion. The device list also shows when each device first joined.
- **Release packaging:** `python tools/build-release.py` builds the manifest-versioned upload ZIP from runtime sources, all files in `icons/` (including SVG), and the 19 locale message files. It verifies resource references, locale key parity, archive inventory, CRCs and byte equality. `--check` verifies the existing archive without rewriting it.
- **Verification and graph availability:** Native Firefox QA uses an isolated temporary profile and a test-only extension copy via `tests/sync-firefox-runner.mjs`; its DOM/browser evidence is saved in `.project/sync-firefox-qa.json`. Current verification uses Node mocks only, per the user's no-launch request. Runtime regressions cover stale YouTube replacement, 1500-record acknowledgement compaction, failed-write preservation and observed clock skew. Codebase Memory MCP and its skill were unavailable in this session. The persisted graph still requires reindexing with `persistence: true` when the MCP becomes available.

## Glossary
- **Workspaces (Пространства)**: Логические группы вкладок, создаваемые пользователем для разделения задач (например, "Главное", "Учеба", "Работа").
- **Auto-Backup (Авто-бэкап)**: Автоматическое резервное копирование состояния пространств и вкладок в `storage.local` с заданной периодичностью.
- **Tab Hiding (Скрытие вкладок)**: Использование API `browser.tabs.hide` / `show` для отображения только вкладок текущего пространства.
- **Host Permissions (Разрешения узлов)**: Разрешения доступа к содержимому веб-сайтов (`<all_urls>`).
- **Pending Assignment (Ожидающее назначение)**: Кратковременный флаг новой вкладки в `pendingTabAssignments`, пока `onCreated` уточняет session/opener — `switchWorkspace` не должен переназначать такие вкладки.
